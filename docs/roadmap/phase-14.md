# Phase 14 — 職員間メッセージ（チャンネル／DM・permission-aware）

> 目的: **人と人が会話する面**を載せる（design §4.14・requirements FR-18）。
> §4.4 のチャット（人と LLM）とは別機能だが、**content blocks・配信・監査・ReBAC はすべて既存の枠に載せる**。
> メッセージ機能のために権限判定を新設しないことが、この Phase の設計上の要。
>
> 完了の定義(DoD): 公開チャンネルを作って招待 → 発言・スレッド返信・リアクション → ドライブの文書を共有し、
> 権限の無い相手には「参照できない添付」として出る → 発言を検索すると自分が参加しているチャンネルと
> 自分あての DM だけが出る → メッセージから対話を起動すると、そのチャンネルの文脈を踏まえた回答が
> **照会者の権限で**返る → 管理者が公開チャンネルをエクスポートでき、DM は承認レコードがある期間だけ
> 読める、が一続きで動く。
>
> **スコープ外**: 音声通話・ビデオ会議・画面共有／外部ユーザーの参加／メッセージの暗号化保管を
> 文書と別扱いにすること／チャンネル横断の全文検索を RAG へ流すこと（発言は RAG の索引に入れない）。
>
> ⚠️ **着手前に [設計上の落とし穴](../design-caveats.md) の PIT-63（チャンネル文脈による権限昇格）・
> PIT-64（メンバーシップ剥奪が購読と索引に伝わらない）・PIT-65（管理者閲覧の相乗り）・
> PIT-66（pub/sub トピックからの `tenant_id` 欠落）を確認すること。**
> 併せて PIT-45（org＝テナント内の隔離境界）・PIT-46（匿名/テナント跨ぎ共有の安全包絡）も前提になる。
>
> 🔒 **human 承認が要るタスク**:
> - **14.2（OpenFGA `channel` relation schema）** — AGENTS.md の「必ず human に確認する」に該当する
>   ポリシ決定。公開チャンネルを `member from parent`（org 継承）で表すか明示タプルにするか、
>   `can_post` を `member` と分けるか、`admin` を org 管理者から継承させるかが未決。
>   **ここを決めないと 14.3 以降が全部やり直しになる。**
> - **14.9（管理者の閲覧・エクスポート）** — DM を誰がどの手続で読めるかはテナントの規程に属する。
>   承認者の定義と保持期間を human と決めてから実装する（PIT-65）。
> - **参加前の発言の可視性** — 後から参加した利用者が過去ログを読めるかはポリシ決定。
>   検索・エクスポート・対話の文脈組み立ての 3 経路すべてに同じ答えを適用する必要がある（PIT-63）。
>
> **外部コミットメント**: 岩手県警察本部向け AI 基盤の調達仕様書案（2026-08-24 提出）6-3(8) および
> 別紙1 M-1〜M-10 に、**必須要件として提示済み**。同案では性能要件として「メッセージの送信から
> 相手方への表示まで 3 秒以内・同時接続 1,000 人」を置いている。納入までに実装が要る。

## 詳細

### Task 14.1: `crates/messaging` ドメイン＋ migration
- **area**: storage / **path**: `crates/messaging`, `migrations/`
- **仕様**: `channel`（`kind` = Public / Private / Dm・`tenant_id`・`org`・`archived_at`）、
  `channel_member`、`message`（`parent_id` でスレッド返信・`blocks` は JSONB）、
  `message_reaction`、`read_state`。**DM は独立テーブルにせず `kind = Dm` のチャンネルとして持つ**
  （検索・監査・配信・保持期間の経路を1本に保つ。グループ DM も同型）。
  **未読は `read_state.last_read_at` からの導出**とし、既読フラグを行ごとに持たない
  （1,000 接続 × 発言数の書き込みを避ける）。migration 番号は既存の最大 +1。
- **受け入れ条件**:
  - [ ] DM の作成が同一メンバー集合で冪等（重複チャンネルができない）
  - [ ] `tenant_id` を伴わない取得経路が存在しない（型で強制）
  - [ ] `bash scripts/check-migration-versions.sh` が通る

### Task 14.2: OpenFGA `channel` 型と relation 🔒
- **area**: authz / **path**: `crates/authz`, FGA モデル定義
- **仕様**: `channel` 型に `member` / `admin` / `parent`（→ `org`）。公開チャンネルを
  `member from parent` で表すか、参加操作で明示タプルを張るかを **human と決める**。
  前者は「全員が読める」が自然に出るが、退出の概念を持てない。後者は退出を表せるが、
  組織に人が増えたときの追従を別途要する。`can_post` を `member` と分けるか、
  `admin` を org 管理者から継承させるかも同時に決める。
- **受け入れ条件**:
  - [ ] 決定事項が design §4.14 に反映されている（docs が正本）
  - [ ] 非メンバーが非公開チャンネルを読めない negative テスト
  - [ ] relation の変更が codegen 経由で Rust / TS の双方に伝わる

### Task 14.3: メッセージ API
- **area**: api / **path**: `crates/api`
- **仕様**: 投稿・編集・削除（論理削除）・スレッド返信・リアクション。**本文は §4.4 の content blocks の
  部分集合**（`text` / `file_ref` / `mention`）で、チャットとブロックの型を分けない。
  権限は OpenFGA クライアントの単一チョークポイント経由。
- **受け入れ条件**:
  - [ ] 投稿・編集・削除がすべて `AuthContext` 経由で認可される
  - [ ] blocks の型が FR-4 と共有され、TS 型が codegen から出る

### Task 14.4: リアルタイム配信
- **area**: api / **path**: `crates/api`
- **仕様**: SSE ＋ Redis pub/sub。**トピック名は `{tenant_id}:channel:{id}`** で、組む関数を1つに閉じる
  （PIT-66）。購読開始時に FGA を引くだけでは足りない。**メンバーシップ剥奪イベントで接続へ leave を
  push し、あわせて購読の再評価に上限 TTL を置く**（push を取りこぼしても有限時間で閉じる・PIT-64）。
- **受け入れ条件**:
  - [ ] 購読中に剥奪された接続へ、以後の発言が届かない
  - [ ] 別テナントで同じ `channel_id` を持つ行を作っても配信が混ざらない（結合テスト）
  - [ ] 1,000 接続で表示遅延が 3 秒以内（14.16 で計測）

### Task 14.6: `file_ref` ブロック
- **area**: storage/api / **path**: `crates/messaging`, `crates/api`, `web/`
- **仕様**: `file_ref` は **file_id を持つだけで本文を複製しない**。表示のたびに StorageService 経由で
  ReBAC を評価し、権限が無い相手には「参照できない添付」として出す。
- **受け入れ条件**:
  - [ ] 共有後に文書の権限を絞ると、過去の発言からも見えなくなる
  - [ ] 権限の無い相手にファイル名・サイズ等のメタデータが漏れない

### Task 14.7: 発言の全文検索
- **area**: rag/api / **path**: `crates/rag`, `crates/api`
- **仕様**: **発言は RAG の索引に入れない。**専用コレクションを全文検索側に持つ。二段 authz は RAG と
  同型で、pre-filter が「検索者が member のチャンネル」に絞り、post-filter が結果の `channel_id` を
  再評価する。**索引にメンバーシップを焼き込まない**（PIT-64）。
- **受け入れ条件**:
  - [ ] 退出したチャンネルの発言が検索に出ない
  - [ ] pre-filter を意図的に無効化しても post-filter だけで権限が守られる（片系故障テスト）

### Task 14.8: メッセージからの対話呼出し
- **area**: ai / **path**: `crates/agent-core`, `crates/api`
- **仕様**: agent-core を呼ぶ。`AuthContext` は**照会者**のもの。**文脈を組む関数を1箇所に閉じ、
  照会者の `AuthContext` で messaging を読み直した結果だけを渡す**。呼び出し側が message 配列を
  持ち回れる API にしない（PIT-63）。参照文書側は RAG の二段 authz が守る。
- **受け入れ条件**:
  - [ ] 非公開チャンネルの発言を含むスレッドから非メンバーが起動しても、その発言が回答に出ない（negative e2e）
  - [ ] 参加前の発言の可視性が、検索・エクスポート・文脈組み立ての3経路で一致する

### Task 14.9: 管理者の閲覧・エクスポート 🔒
- **area**: api / **path**: `crates/api`
- **仕様**: **通常の read 経路に相乗りさせない。**専用の管理 API に分け、公開チャンネルは管理者ロールで、
  DM と非公開チャンネルは**承認レコード（承認者・対象・期間）がある期間内だけ**許可する。
  全操作を `audit_log` へ落とす。承認者の定義は設定可能にする（PIT-65）。
- **受け入れ条件**:
  - [ ] 管理者ロールで DM が一覧・検索・対話文脈のいずれにも出ない（negative）
  - [ ] 承認レコードの期間外でエクスポートが失敗する
  - [ ] 閲覧・エクスポートの全操作が監査に残る

### Task 14.16: 受入試験
- **area**: qa / **path**: `crates/*/tests`, `web/e2e`
- **仕様**: 権限の negative を主軸に置く。剥奪の伝播（購読・検索・文脈）、テナント越境、
  管理者閲覧の分離。あわせて同時接続 1,000 での表示遅延を計測する（外部コミットメントの 3 秒）。
- **受け入れ条件**:
  - [ ] PIT-63〜66 それぞれに対応する negative テストが存在する
  - [ ] 1,000 接続で送信から表示まで 3 秒以内
