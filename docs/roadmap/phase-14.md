# Phase 14 — 職員間メッセージ（チャンネル／DM・permission-aware）

> 目的: **人と人が会話する面**を載せる（design §4.14・requirements FR-18）。
> §4.4 のチャット（人と LLM）とは別機能だが、**content blocks・配信・監査・ReBAC はすべて既存の枠に載せる**。
> メッセージ機能のために権限判定を新設しないことが、この Phase の設計上の要。
>
> 完了の定義(DoD): 公開チャンネルを作って招待 → 発言・スレッド返信・リアクション → ドライブの文書を共有し、
> 権限の無い相手には「参照できない添付」として出る → 発言を検索すると自分が参加しているチャンネルと
> 自分あての DM だけが出る → メッセージから対話を起動すると、そのチャンネルの文脈を踏まえた回答が
> **照会者の権限で**返る → 監査担当者が公開チャンネルをエクスポートでき、DM は承認レコードがある期間だけ
> 読める、が一続きで動く。
>
> **スコープ外**: 音声通話・ビデオ会議・画面共有／外部ユーザーの参加／メッセージの暗号化保管を
> 文書と別扱いにすること／チャンネル横断の全文検索を RAG へ流すこと（発言は RAG の索引に入れない）。
>
> ⚠️ **着手前に [設計上の落とし穴](../design-caveats.md) の PIT-63（チャンネル文脈による権限昇格）・
> PIT-64（メンバーシップ剥奪が購読と索引に伝わらない）・PIT-65（管理者閲覧の相乗り）・
> PIT-66（pub/sub トピックからの `tenant_id` 欠落）を確認すること。**
> 併せて PIT-45（org＝テナント内の隔離境界）・PIT-46（匿名/テナント跨ぎ共有の安全包絡）も前提になる。
>
> ✅ **human 決定（2026-11）**: 14.2 の relation schema、参加前の発言の可視性、14.9 の閲覧手続、
> 保存期間・編集削除・チャンネル運用・メンション・書式は確定し、design §4.14 に反映した。
>
> ✅ **human 決定（2026-11・追加）**: `folder` / `file` の viewer に `channel#member` を受理させる（資料のチャンネル
> 共有・閲覧だけ）。非公開チャンネルは組織のメンバーなら誰でも作れる。いずれも design §4.14 に反映した。
>
> 🔒 **残る human 承認事項**:
> - 法務: 初回利用時の同意画面・電気通信事業の届出ほか（[launch-compliance §7](../legal/launch-compliance.md)）。
>
> **規模と応答の目安**: 同時接続は登録利用者数と同数（オンプレ構成では 1,000）。
> 送信から相手方への表示まで 3 秒以内。
> 閉域環境では外部のチャットツールを併用できないため、本機能が会話面の唯一の手段になる。

## 詳細

### Task 14.1: `crates/messaging` ドメイン＋ migration
- **area**: storage / **path**: `crates/messaging`, `migrations/`
- **仕様**: `channel`（`kind` = Public / Private / Dm・`tenant_id`・`org`・`archived_at`）、
  `channel_member`（`visible_from`＝参加・入り直しの時刻）、`message`（`parent_id` でスレッド返信・
  入れ子は 1 段・`blocks` は JSONB・編集前／削除前の本文を保存期間まで保持）、`message_reaction`、`read_state`。
  **DM は 1 対 1 に限り、独立テーブルにせず `kind = Dm` のチャンネルとして持つ**（検索・監査・配信・
  保存期間の経路を1本に保つ。3 人以上は非公開チャンネル）。チャンネル名は org 内で一意（公開・非公開とも）。
  全テーブルは `(tenant_id, org)` を持ち、チャンネルは 1 つの org に閉じる。
  **未読は `read_state.last_read_at` からの導出**とし、既読フラグを行ごとに持たない
  （1,000 接続 × 発言数の書き込みを避ける）。migration 番号は既存の最大 +1。
- **受け入れ条件**:
  - [x] 同じ 2 人の DM の作成が冪等（重複チャンネルができない）
  - [x] 非公開・DM の読取が `visible_from` より前の発言を返さない（境界を掛ける関数は 1 つ）
  - [x] `tenant_id` を伴わない取得経路が存在しない（型で強制）
  - [x] `bash scripts/check-migration-versions.sh` が通る

### Task 14.2: OpenFGA `channel` 型と relation
- **area**: authz / **path**: `crates/authz`, FGA モデル定義
- **仕様**: human 承認済みの schema（design §4.14）。`parent`（→ `organization`）・`admin`（明示付与のみ・
  org 管理者から継承しない）・`member`（`[user] or admin`・公開でも参加は明示タプル）・`org_reader`
  （公開チャンネルだけ `organization#member` を書く）・`poster`（通常は `channel#member`、アナウンス専用は個別）・
  `can_read = member or org_reader`・`can_join = org_reader`・`can_post = poster and member`・`can_manage = admin`。
- **受け入れ条件**:
  - [x] 決定事項が design §4.14 に反映されている（docs が正本）
  - [x] 非メンバーが非公開チャンネルを読めない・org 管理者が継承しない・退出で投稿できなくなる・
        テナントを越えない negative テスト
  - [x] relation の変更が codegen 経由で Rust / TS の双方に伝わる

### Task 14.3: メッセージ API
- **area**: api / **path**: `crates/api`
- **仕様**: チャンネルの作成・参加・招待・退出・アーカイブ、DM の開始、投稿・編集・削除（論理削除）・
  スレッド返信・リアクション。**本文は §4.4 の content blocks の部分集合**（`text` / `file_ref` / `mention`）で、
  チャットとブロックの型を分けない。上限は 1 発言 4,000 文字・添付 10 件。権限は OpenFGA クライアントの
  単一チョークポイント経由。運用ルール（design §4.14）: 公開チャンネルは誰でも作れる（org 設定で絞れる）／
  最後の `admin` は退出できない／1 対 1 の DM は退出できず非表示だけ／編集は本人だけ（期限なし）／
  削除は本人とチャンネルの `admin`／編集履歴は他の人に見せない／無効化された利用者の発言は残す。
- **受け入れ条件**:
  - [x] 投稿・編集・削除がすべて `AuthContext` 経由で認可される
  - [x] 編集前・削除前の本文が通常の読取・検索・対話文脈に出ない（管理者閲覧の手続でだけ読める）
  - [x] blocks の型が FR-4 と共有され、TS 型が codegen から出る

### Task 14.4: リアルタイム配信
- **area**: api / **path**: `crates/api`
- **仕様**: SSE ＋ Redis pub/sub。**トピック名は `{tenant_id}:channel:{id}`** で、組む関数を1つに閉じる
  （PIT-66）。購読開始時に FGA を引くだけでは足りない。**メンバーシップ剥奪イベントで接続へ leave を
  push し、あわせて購読の再評価に上限 TTL を置く**（push を取りこぼしても有限時間で閉じる・PIT-64）。
- **受け入れ条件**:
  - [x] 購読中に剥奪された接続へ、以後の発言が届かない
  - [x] 別テナントで同じ `channel_id` を持つ行を作っても配信が混ざらない（結合テスト）
  - [x] 1,000 接続で表示遅延が 3 秒以内（14.16 で計測）

### Task 14.6: `file_ref` ブロック
- **area**: storage/api / **path**: `crates/messaging`, `crates/api`, `web/`
- **仕様**: `file_ref` は **file_id を持つだけで本文を複製しない**。表示のたびに StorageService 経由で
  ReBAC を評価し、権限が無い相手には「参照できない添付」として出す。
- **受け入れ条件**:
  - [x] 共有後に文書の権限を絞ると、過去の発言からも見えなくなる
  - [x] 権限の無い相手にファイル名・サイズ等のメタデータが漏れない

### Task 14.7: 発言の全文検索
- **area**: rag/api / **path**: `crates/rag`, `crates/api`
- **仕様**: **発言は RAG の索引に入れない。**専用コレクションを全文検索側に持つ。二段 authz は RAG と
  同型で、pre-filter が「検索者が member のチャンネル」に絞り、post-filter が結果の `channel_id` を
  再評価する。**索引にメンバーシップを焼き込まない**（PIT-64）。
- **受け入れ条件**:
  - [x] 退出したチャンネルの発言が検索に出ない
  - [x] pre-filter を意図的に無効化しても post-filter だけで権限が守られる（片系故障テスト）

### Task 14.8: メッセージからの AI 呼出し（`@シキ`）
- **area**: ai / **path**: `crates/agent-core`, `crates/messaging`, `crates/api`
- **仕様**: agent-core を呼ぶ。シキは独自の権限を持たず（新しい `PrincipalKind` を作らない）、`AuthContext` は
  **照会者**のもの。**文脈を組む関数を1箇所に閉じ、照会者の `AuthContext` で messaging を読み直した結果だけを
  渡す**。呼び出し側が message 配列を持ち回れる API にしない（PIT-63）。参照文書側は RAG の二段 authz が守る。
  - **公開返信（既定）**: チャンネル内の発言と、チャンネルに共有した資料（`channel#member` が viewer の文書）
    だけを根拠にする。
  - **自分だけに表示**: 照会者の権限で答える回答は照会者だけに見せる。照会者が明示的に投稿したときだけ公開し、
    投稿の直前に「一部の参加者が読めない資料」を知らせる（止めない）。
  - チャンネル内で AI が使える道具は既定で読み取り系だけ。書き込み系は照会者の承認を通す。
- **受け入れ条件**:
  - [x] 非公開チャンネルの発言を含むスレッドから非メンバーが起動しても、その発言が回答に出ない（negative e2e）
  - [x] 参加前の発言の可視性が、検索・エクスポート・文脈組み立ての3経路で一致する
    （境界は `store_message::fetch_messages` の 1 か所。監査担当者のエクスポートは design §4.14 のとおり別経路で、承認レコードの期間・範囲で絞る）
  - [x] 公開返信の根拠に、チャンネルに共有されていない資料が入らない（negative）
    （実行部はチャンネルに共有された文書だけを根拠にし、messaging 側でも FGA で確かめる。1 件でも共有されていない文書が
    混ざれば公開せず本人だけに表示する: `public_reply_is_grounded_on_channel_shared_documents_only`）

### Task 14.17: AI によるチャットの作成と承認の通知
- **area**: ai / **path**: `crates/agent-core`, `crates/chat`, `crates/messaging`
- **仕様**: シキが必要と判断したとき、または照会者が頼んだときに、チャット（§4.4 のスレッド・エージェント
  モードに限らない）を作り、作業をそちらで進める。**持ち主と実行者は照会者**で、権限は増えない。
  チャットの中の承認はシキが出すが、**照会者の承認モード設定で自動承認される操作まで**。それ以外は人の承認に回し、
  **シキが照会者への DM で通知**して承認カードへのリンクを付ける。承認できるのは照会者本人だけ。
- **受け入れ条件**:
  - [x] 承認必須モードの照会者では、シキが何も承認せず全件が DM 通知になる
  - [x] 照会者の自動承認範囲を超える操作（不可逆操作など）をシキが承認できない（negative）
    （シキは承認の経路を持たない。チャットは照会者の既定の承認モードで作り、承認待ちは照会者への DM で知らせる）
  - [x] 作られたチャットの持ち主が照会者で、チャンネルの他の参加者には見えない

### Task 14.20: パーソナルエージェントの名前とアイコン
- **area**: api/frontend / **path**: `crates/messaging`, `crates/api`, `web/`
- **仕様**: 利用者ごとに名前とアイコンを設定できる（未設定なら「シキ」と既定のアイコン）。**呼べるのは持ち主本人だけ**。
  名前とアイコンは見た目だけで、権限・承認・道具に影響しない。発言には「〇〇 のエージェント」と持ち主を必ず表示する。
  実在の利用者名や「シキ」「管理者」と紛らわしい名前は拒否する。アイコンはプロフィール画像と同じ置き場・制限。
- **受け入れ条件**:
  - [x] 他人のエージェント名でメンションしても起動しない（negative）
  - [x] 実在の利用者名・紛らわしい名前の設定が拒否される

### Task 14.9: 管理者の閲覧・エクスポート
- **area**: api / **path**: `crates/api`
- **仕様**: **通常の read 経路に相乗りさせない。**専用の管理 API に分け、閲覧するのは**監査担当者
  （`organization#audit_viewer`）**で、管理者（`admin`）には与えない。公開チャンネルは承認レコード不要。
  DM と非公開チャンネルは**承認レコード（申請者・承認者・理由・対象・期間）がある期間内だけ**許可する。
  承認者はテナントが指名し、申請者本人は承認できず、未設定なら閲覧できない。対象はチャンネル単位＋発言の期間
  （利用者単位は許さない）。期間は既定 7 日・最長 30 日。読まれた本人には通知しない。エクスポートは期限付きの
  ダウンロードで、ドライブには保存しない。全操作を `audit_log` へ落とす（PIT-65）。
- **受け入れ条件**:
  - [x] 管理者ロール・監査担当者のどちらでも、承認レコード無しで DM が一覧・検索・対話文脈のいずれにも出ない（negative）
  - [x] 申請者本人の承認・承認者未設定・期間外のいずれでも閲覧とエクスポートが失敗する
  - [x] 閲覧・エクスポートの全操作が監査に残る

### Task 14.18: 保存期間
- **area**: api / **path**: `crates/messaging`, `crates/api`
- **仕様**: 監査ログとは別の設定で、**既定は無期限**。期限を設定する場合も監査ログの保存期間より短くできない。
  期限で削除した発言は検索の索引からも消し、表示は「この発言は保存期間を過ぎました」（スレッドの返信は残す）。
- **受け入れ条件**:
  - [x] 監査より短い期限の設定が拒否される
  - [x] 期限で消えた発言が検索・対話文脈・管理者閲覧のいずれにも出ない

### Task 14.19: リンクのプレビュー
- **area**: api / **path**: `crates/messaging`, `crates/api`
- **仕様**: 取得できる構成では出す。取得は `crates/web-access` の `public_fetch` だけを通す（PIT-48）。
  外部接続を持たない構成（エアギャップ・テナントが外部アクセスを止めた構成）では出さない
  （NFR-2 の外部接続必須機能に区分）。
- **受け入れ条件**:
  - [x] 社内アドレス・メタデータエンドポイントへの URL でプレビューを取得しない（negative）
  - [x] 外部接続の無い構成でプレビュー取得が走らない

### Task 14.16: 受入試験
- **area**: qa / **path**: `crates/*/tests`, `web/e2e`
- **仕様**: 権限の negative を主軸に置く。剥奪の伝播（購読・検索・文脈）、テナント越境、
  管理者閲覧の分離。あわせて同時接続 1,000 での表示遅延を計測する（目安 3 秒）。
- **受け入れ条件**:
  - [x] PIT-63〜66 それぞれに対応する negative テストが存在する
  - [x] 1,000 接続で送信から表示まで 3 秒以内
