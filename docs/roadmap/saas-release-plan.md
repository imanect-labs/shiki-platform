## 2. AI 実行の運用ルール

- **1 バッチ = 1 つの AI 作業単位**。バッチ内は同一領域に閉じており、複数 PR に分割してよい（1 PR = 1 Issue の
  dev-workflow スキル準拠。バッチ着手時に、含まれるタスクを Issue 化してから実装する）。
- **依存**列にあるバッチが完了するまで着手しない。**要決断**列がある場合は human の決定（§5）を得てから着手する。
- 各バッチの**完了条件**が検収基準。PR の説明に完了条件との対応を書くこと。
- 着手前に `docs/design-caveats.md` の該当 PIT と architecture-invariants スキルを確認する（従来どおり）。
- Wave は目安の順序。**同一 Wave 内のバッチは原則すべて並行実行可能**（対象パスが重ならないよう分割してある。
  例外は依存列に明記）。

#### W2-5 顧客管理者ダッシュボード＋同意/委譲棚卸し（12.2/12.3）

#### W2-6 ベンダーコンソール＋break-glass（12.4/12.5）
