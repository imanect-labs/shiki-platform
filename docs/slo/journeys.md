# 利用者の流れ（ジャーニー）の台帳

SLO を割り当てる元になる台帳。[README.md](./README.md) §1 の原則 2 に従い、台帳の流れは SLO（T1・T2）か監視指標（T3）のどれかで必ず守る。
数値は各領域の文書にだけ書く。実装状況は 2026-11-27 時点（コードと roadmap から確認）。

## 1. 重要度の付け方

| 重要度 | 基準 |
| --- | --- |
| 高 | 止まると業務が止まる。毎日多くの利用者が使う |
| 中 | 止まると不便だが、回避策がある・使う人が限られる |
| 低 | 管理者だけが使う・遅れても気づかれにくい |

依存の略: PG=Postgres、FGA=OpenFGA、KC=Keycloak、OS=オブジェクトストア（RustFS／GCS）、Rd=Redis、Qd=Qdrant、Tv=Tantivy、IW=ingestion-worker、LLM=llm-gateway 経由の推論、SBX=sandbox-orchestrator、WS=Web 検索、CO=Collabora。

## 3. システムの流れ

利用者の操作に直接はつながらないが、止まると後で利用者に影響が出るもの。

| 流れ | 状況 | 守る SLO／指標 |
| --- | --- | --- |
| outbox → relay → 各コンシューマ（RAG・ワークフロー・ミニアプリ） | 実装 | EV-1・EV-2・ING-1 |
| ジョブキュー（jobq）の各キュー | 実装 | JOB-1・JOB-2（T3） |
| ワークフローのスケジューラ（リーダー 1 つ） | 実装 | WF-2・先行指標（リーダー不在） |
| チャットの孤児 run の回収 | 実装 | CHAT-8 |
| 中断アップロード・outbox・終わった run の GC | 実装 | JOB-2（T3） |
| 監査ログの保持期限による削除 | 実装 | OPS-5（T3） |
| バックアップ・復元 | 計画（Task 12.10） | OPS-2・OPS-3・[dependencies.md §5](./dependencies.md#5-復旧目標rpo--rto) |
| 証明書・DNS | 運用 | OPS-6（T3） |
| 不具合報告の配送 | 実装（既定は無効） | OPS-7（T3） |

## 4. 台帳の保守

- 機能を足したら、この台帳に行を足し、守る SLO か監視指標を決める。決めずに出さない。
- 「計画」の行は、実装の PR で SLO を有効にする（数値は実装時の計測から〔測〕で置く）。
