# outbox → job_queue 経路のフルプール実測（#818・2026-10-22）

生成: docs/events/bench/outbox-pool-bench.sh（emit / mixed / scan / jobs の出力を連結。NOTICE 行は除去）。
機材: docker の PostgreSQL 16.15（Alpine）・既定設定・4 vCPU を他のビルドと共有（loadavg 3〜15）。絶対値ではなく伸び方を見ること。
emit の WAL/イベントは pg_current_wal_lsn（クラスタ全体）の差分なので、同居 DB の書込を含む上限値である。

実行時刻と、スクリプトの版:
- emit 10:24Z・jobs 10:41Z: 初版。emit と jobs の計測ロジックは最終版と同じ。
- mixed 3 本（11:44〜11:49Z）・scan（11:49〜11:55Z）: 最終版で再実行した。最終版で直したのは次の点。
  - relay レイテンシを payload.relayed_at（INSERT 時の clock_timestamp()）− created_at で測る。
    初版は enqueued_at（relay txn 開始の now()）を使っており、過小・負値になり得た。
  - event_type を各テナントに 1 割ずつ配る（初版は g % 10 で、番号が 0 で終わるテナントにしか付かなかった）。
  - 活動中テナントの SSE カーソルを、自社の 1 つ前の event_type イベントに置く（走査窓の行数をラベルに出す）。
  - 休眠テナントの SSE poll（カーソル 0）を追加した。
  - 安全柵を current_database() の ^shiki_[0-9]+$ 照合にした。
  - mixed の wait を pid ごとにした。
