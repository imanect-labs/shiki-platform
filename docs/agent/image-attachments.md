# チャットの画像添付

画像のfile_refは名前だけでなく、投稿者のAuthContextでStorageServiceから読み出し、LLMの画像ブロックとして送る。通常チャットとエージェントで共通の履歴構築を使う。

- 対応形式: PNG / JPEG / GIF / WebP。画像形式は実バイトのシグネチャで決める。
- 新しいユーザー添付から最大4枚、1枚4MiB、縦横それぞれ8,000pxまで（ヘッダーのみで寸法を検査）。ファイル名の画像拡張子を候補判定に使い、SVG / AVIF / BMPは非対応の注記を返す。
- 同じnode_idの画像は最新の参照だけを送る。選んだ画像の読込は最大4並列に制限し、投稿内の画像順は保つ。assistantの成果物を自動で画像入力として追加しない。
- サイズ超過・非対応形式・読み出し失敗は、画像を見ていないことをモデルに明示する。
- ブラウザのURL・外部URL・署名付きURLをモデルへ渡さない。認可済みの画像実体をbase64で送る。
- 画像実体は共有参照で保持し、Debugやチェックポイントに保存しない。再開時は現在の権限で再読込した画像だけを復元する。
- OpenAI互換Chat Completions、Responses、Anthropicそれぞれの画像入力形式へ変換する。選択するモデル自体にも画像入力対応が必要。

## エージェントによるファイル複製

`drive.copy` は元ファイルの閲覧権限と複製先の作成権限をStorageService経由で確認し、新しいファイルを作成する。実行前の承認は維持する。

`node_id` と拡張子を保った `new_name` が必須。`destination_folder_id` は省略で元と同じフォルダ、`root` でマイドライブ直下。フォルダの再帰複製は対象外（#1107）。読み出しの上限は50MiBで、書き込みにはStorageServiceのアップロード上限も適用する。

元ファイルの内容・版・共有設定は変更しない。元の共有設定や版履歴を新しいファイルにコピーせず、新しい保存先から権限を継承する。同名ファイルがあれば上書きせず、別名を求める。保存に伴う監査・索引イベントは通常の新規作成と同じ経路を通す。同じrun・実行者・引数で再実行したときはStorageServiceのeffect_journalで重複作成を防ぎ、同じ複製結果を復元する。元ファイルが更新・移動・削除されても、現在複製結果を閲覧できる場合に限り復元し、削除済みの複製を再作成しない。ノート・スライドは保存待ちのblobではなく最新の共同編集状態から複製する。計画段階では複製ツールを提示せず、実行段階から提示する。
